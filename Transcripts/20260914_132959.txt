[00:00:00 - 00:20:00]
อาจารย์: วันนี้เรามาดูเรื่องของ Routing Algorithm ต่อนะคะ
คราวที่แล้วเราดูเรื่อง Link State (Dijkstra's Algorithm) ไปแล้ว วันนี้เรามาดูอัลกอริทึมประเภทที่ 2 คือ Distance Vector (DV) Routing Algorithm
ในกราฟเครือข่าย เรามีโหนด u, v, w, x, y, z และมีลิงก์เชื่อมต่อระหว่างโหนด แต่ละลิงก์มีค่าน้ำหนักหรือ Cost กำกับอยู่
สมการพื้นฐานของ Distance Vector คือสมการของ Bellman-Ford:
d_x(y) = min_v { c(x,v) + d_v(y) }
โดยที่:
- d_x(y) คือ Cost ต่ำสุดจากโหนด x ไปยังโหนด y
- min_v คือหาค่าต่ำสุดจากบรรดาเพื่อนบ้าน (Neighbors) v ทั้งหมดของ x
- c(x,v) คือ Cost ของลิงก์ตรงจาก x ไปยังเพื่อนบ้าน v
- d_v(y) คือ Cost ต่ำสุดจากเพื่อนบ้าน v ไปยังปลายทาง y

[00:20:00 - 00:45:00]
อาจารย์: ตัวอย่างการคำนวณจากโหนด u ไปยังปลายทาง z:
โหนด u มีเพื่อนบ้าน (Neighbors) ที่เชื่อมต่อโดยตรง 3 โหนด คือ v, x, และ w
จากข้อมูล Distance Vector ที่ได้รับจากเพื่อนบ้าน:
- ผ่านทาง v: c(u,v) = 2, d_v(z) = 5 -> รวมเป็น 2 + 5 = 7
- ผ่านทาง x: c(u,x) = 1, d_x(z) = 3 -> รวมเป็น 1 + 3 = 4
- ผ่านทาง w: c(u,w) = 5, d_w(z) = 3 -> รวมเป็น 5 + 3 = 8
หาค่าน้อยที่สุด:
min { 7, 4, 8 } = 4
ดังนั้น ค่าใช้จ่ายต่ำสุดจาก u ไปยัง z คือ 4 โดยต้องส่งแพ็กเก็ตผ่านทางเพื่อนบ้าน x (Next Hop = x)
ตาราง Forwarding Table ของ u จึงบันทึกว่า: ปลายทาง z ให้ส่งออกทางอินเทอร์เฟซที่ต่อกับ x

[00:45:00 - 01:10:00]
อาจารย์: คุณลักษณะของ Distance Vector:
1. Distributed: แต่ละโหนดรับข้อมูลเฉพาะจากเพื่อนบ้านโดยตรง (Direct Neighbors) เท่านั้น ไม่จำเป็นต้องรู้แผนผังเครือข่ายทั้งโลกเหมือน Link State
2. Iterative & Asynchronous: แต่ละโหนดจะคำนวณใหม่เฉพาะเมื่อ:
   - Cost ของลิงก์ที่ต่ออยู่กับตัวเองเปลี่ยนไป
   - ได้รับเวกเตอร์อัปเดตใหม่จากเพื่อนบ้าน
3. เมื่อคำนวณเสร็จ หากค่า Distance Vector ของตัวเองเปลี่ยน จึงจะส่งกระจายเวกเตอร์ใหม่ไปให้เพื่อนบ้าน ถ้าค่าไม่เปลี่ยน ก็ไม่ต้องส่ง

ปัญหาสำคัญของ Distance Vector:
- ข้อดี: "Good news travels fast" ถ้ามีลิงก์ใหม่หรือ Cost ลดลง ข้อมูลจะคอนเวอร์จอย่างรวดเร็ว
- ข้อเสีย: "Bad news travels slow" และปัญหา Count-to-Infinity Problem!
เมื่อลิงก์ขาดหรือ Cost เพิ่มสูงขึ้นอย่างมาก โหนดข้างเคียงจะเกิด Routing Loop วนส่งข้อมูลไปมาระหว่างกัน ค่า Cost จะค่อยๆ เพิ่มทีละ 1 นับไปเรื่อยๆ จนถึงค่าอนันต์ (Infinity) กว่าระบบจะรู้ว่าทางขาด
วิธีบรรเทาปัญหา: ใช้เทคนิค Poisoned Reverse หรือ Split Horizon

[01:10:00 - 01:30:00]
อาจารย์: หัวข้อถัดไป: Hierarchical Routing (การหาเส้นทางแบบลำดับชั้น)
ในโลกความเป็นจริง เครือข่ายอินเทอร์เน็ตมีเราเตอร์เป็นพันๆ ล้านตัว เราไม่สามารถทำ Flat Routing ให้ทุกเราเตอร์เก็บข้อมูลปลายทางทุกตัวในโลกได้ เพราะ:
1. Scale: ขนาด Routing Table จะใหญ่โตเกินความจุหน่วยความจำ และทราฟฟิกแลกเปลี่ยนข้อมูลจะล้นเครือข่าย
2. Administrative Autonomy: แต่ละองค์กร เช่น มหาวิทยาลัย หรือ ISP ย่อมต้องการจัดการและควบคุมเครือข่ายภายในของตนเองอย่างเป็นอิสระ

ทางออกคือการแบ่งเครือข่ายออกเป็น Autonomous Systems (AS):
1. Intra-AS Routing (การหาเส้นทางภายใน AS เดียวกัน):
   - รู้จักกันในชื่อ Interior Gateway Protocols (IGP)
   - เราเตอร์ทั้งหมดใน AS เดียวกันต้องใช้โปรโตคอลเดียวกัน
   - โปรโตคอลยอดนิยม: OSPF (Open Shortest Path First - ใช้ Link State), RIP (Routing Information Protocol - ใช้ Distance Vector)
2. Inter-AS Routing (การหาเส้นทางระหว่าง AS ต่างกัน):
   - รู้จักกันในชื่อ Exterior Gateway Protocols (EGP)
   - โปรโตคอลมาตรฐานที่ใช้ทั่วโลกคือ BGP (Border Gateway Protocol)
   - ทำงานผ่าน Gateway Routers ที่อยู่ตรงขอบของแต่ละ AS เชื่อมต่อระหว่างกันค่ะ
