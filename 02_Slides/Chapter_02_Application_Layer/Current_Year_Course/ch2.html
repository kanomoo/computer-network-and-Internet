Network Model Foundations

What is a model? What is a network model?

▣

What is a model?

A model is a simplified way to represent a real system or process. It shows the important parts, the order of work, and how the parts relate to each other.

simplifies reality
shows important parts
helps explain a process
⇄

What is a network model?

A network model organizes network communication into layers. Each layer has a clear responsibility, such as application service, delivery control, routing, local link delivery, or signal transmission.

layers
responsibilities
communication process
Map modelShows roads and places, not every real object.
House planShows rooms, doors, and layout before building.

School timetableShows classes by time and order.
Key idea: first understand a model as a simplified explanation of a real process; then a network model becomes easier to understand as a layered explanation of communication.

A Real-Life Layered Model: Booking a Flight

In real life, one task often has several ordered responsibilities. Booking a flight is not one action: we decide the goal, book details, follow a route, board locally, and finally travel physically. This is a simple layered model before comparing it with a network model.

Layering Readiness: Why Models and Layers Matter

Why use a network model?

A model turns a complex network task into smaller responsibilities, so we can learn, design, and troubleshoot step by step.

①Divide the taskBreak communication into smaller jobs.
②Assign one main jobEach layer focuses on a clear responsibility.
③Connect neighborsA layer uses the layer below and serves the layer above.
④Use common rulesPeer layers follow the same protocol rules.

2.5 Protocols

What Is a Protocol?

Protocol is ...

A shared set of communication rules

A protocol tells devices how to format messages, what each part means, and when to send or respond.

{ }

1. Syntax

Message format and structure: fields, headers, order, size, and payload.

🔎

2. Semantics

Meaning of each field: address, port, flag, status code, or command.

⏱️

3. Timing

When to send, wait, reply, retransmit, acknowledge, or control speed.

HTTPGET request → web response
DNSName query → IP address answer
TCPPort + sequence + ACK rules
EthernetFrame + MAC + FCS rules
Key idea: Without the same protocol, devices may send signals, but they cannot correctly understand each other.
