อาจารย์: สวัสดีค่ะทุกคน วันนี้เราขึ้นบทเรียนเรื่อง Data Link Layer นะคะ
ในสถาปัตยกรรมคอมพิวเตอร์ การทำงานของ Link Layer จะเกิดขึ้นทั้งในระดับซอฟต์แวร์ (OS, ไดรเวอร์), เฟิร์มแวร์, และฮาร์ดแวร์บนการ์ดแลน (NIC: Network Interface Card / Network Adapter)
- ฝั่งส่ง (Transmitting Host): รับ Datagram จาก Network Layer มาทำ Encapsulation ห่อหุ้มเป็น Frame โดยใส่ Header, Trailer, และบิตสำหรับตรวจสอบข้อผิดพลาด (EDC: Error-Detection and Correction Bits) แล้วส่งออกทางสายสัญญาณผ่านคอนโทรลเลอร์
- ฝั่งรับ (Receiving Host): รับ Frame จากสายสัญญาณ ตรวจสอบบิต EDC หากไม่พบข้อผิดพลาด จะทำ Decapsulation ปอก Header/Trailer ออก แล้วส่ง Datagram ขึ้นสู่ Network Layer

อาจารย์: กลไกการตรวจจับข้อผิดพลาด (Error Detection Techniques):
สัญญาณที่ส่งผ่านตัวกลางอาจถูกสัญญาณรบกวน (Noise) ทำให้บิตพลิก (Bit Error จาก 0 เป็น 1 หรือจาก 1 เป็น 0)
เทคนิคที่ใช้มี 3 วิธีหลัก:
1. Parity Checking:
   - Single-bit Parity:
     - Even Parity: เพิ่มบิต Parity เข้าไปเพื่อให้จำนวนเลข 1 ทั้งหมดเป็น "เลขคู่"
     - Odd Parity: เพิ่มบิต Parity เข้าไปเพื่อให้จำนวนเลข 1 ทั้งหมดเป็น "เลขคี่"
     - ข้อจำกัด: ตรวจจับได้เฉพาะกรณีบิตพลิกจำนวนคี่บิต (เช่น 1 บิต) ถ้าพลิก 2 บิตพร้อมกันจะไม่สามารถตรวจจับได้ และไม่สามารถระบุตำแหน่งเพื่อแก้ไขบิตที่ผิดได้
   - Two-Dimensional Parity (2D Parity):
     - จัดเรียงบิตข้อมูลเป็นตารางแถวและคอลัมน์
     - คำนวณ Parity บิตประจำแต่ละแถว และประจำแต่ละคอลัมน์
     - ความสามารถพิเศษ: สามารถ "ตรวจจับและแก้ไขข้อผิดพลาด (Detect & Correct)" กรณีบิตพลิก 1 บิตได้ทันที ณ จุดตัดของแถวและคอลัมน์ที่ผิด!

2. Internet Checksum:
   - นำข้อมูลมาแบ่งเป็นชุดขนาด 16 บิต นำมาบวกกันแบบ 1's Complement Sum
   - ผลลัพธ์สุดท้ายกลับบิต (Invert บิต) ได้เป็นค่า Checksum ใส่ใน Header (ใช้ใน UDP และ TCP)

อาจารย์: 3. Cyclic Redundancy Check (CRC):
เป็นวิธีการที่มีประสิทธิภาพสูงมาก นิยมใช้ในมาตรฐานเครือข่ายความเร็วสูง เช่น Ethernet และ Wi-Fi (CRC-32)
ใช้หลักการทางคณิตศาสตร์ Polynomial Codes และการหารเลขฐานสองด้วยการ XOR (Modulo-2 Arithmetic)
กฎการ XOR:
- เหมือนกัน XOR กันได้ 0 (0 XOR 0 = 0, 1 XOR 1 = 0)
- ต่างกัน XOR กันได้ 1 (0 XOR 1 = 1, 1 XOR 0 = 1)

การแปลงสมการพหุนาม (Polynomial) เป็นบิตตัวหาร (Divisor G):
- ถ้าโจทย์ให้ G = x^3 + x^2 + x + 1 -> มีพจน์ x^3, x^2, x^1, x^0 ครบทุกตำแหน่ง -> แทนด้วยบิต 1 1 1 1
- ถ้าโจทย์ให้ G = x^3 + x + 1 -> พจน์ x^2 หายไป -> แทนด้วยบิต 1 0 1 1
- ถ้าโจทย์ให้ G = x^3 + 1 -> พจน์ x^2 และ x^1 หายไป -> แทนด้วยบิต 1 0 0 1

ขั้นตอนการคำนวณ CRC:
1. กำหนดข้อมูล D และตัวหาร G (ความยาว L บิต)
2. เติมบิต 0 ต่อท้ายข้อมูล D จำนวน L - 1 ตัว
3. ตั้งหารยาวด้วย G โดยใช้การ XOR
4. เศษที่ได้จากการหาร (Remainder R ขนาด L - 1 บิต) คือค่า CRC!
5. เฟรมที่ส่งออกไปจริงคือ: ข้อมูล D ต่อท้ายด้วยค่า R

ตัวอย่างในห้องเรียน:
ข้อมูล D = 1 0 0 1 0 0
ตัวหาร G = 1 1 0 1 (ความยาว L = 4 บิต ดังนั้นต้องเติม 0 จำนวน 3 ตัว)
ตั้งข้อมูลเป็น: 1 0 0 1 0 0 0 0 0
ทำการหารด้วย 1 1 0 1 โดยใช้ XOR:
ได้เศษ R = 0 0 1
ดังนั้น CRC = 001
และเฟรมที่ส่งออกไปคือ: 1 0 0 1 0 0 0 0 1
เมื่อฝั่งรับได้รับ 1 0 0 1 0 0 0 0 1 นำมาหารด้วย 1 1 0 1 ได้เศษเป็น 0 พอดี -> ยืนยันว่าข้อมูลถูกต้องสมบูรณ์!

[01:20:00 - 02:00:00]
อาจารย์: หัวข้อถัดไป: Multiple Access Protocols (MAC Protocols)
เมื่อหลายโหนดต้องส่งข้อมูลผ่านตัวกลางหรือช่องสัญญาณร่วมกัน (Shared Broadcast Channel) เช่น สายเคเบิล หรือคลื่นวิทยุ หากส่งพร้อมกันจะเกิดการชนกันของสัญญาณ (Collision)
โปรโตคอลจัดการการเข้าถึงตัวกลางแบ่งเป็น 3 กลุ่ม:
1. Channel Partitioning Protocols:
   - TDMA (Time Division Multiple Access): แบ่งเวลาเป็นสล็อต โหนดส่งได้เฉพาะในสล็อตเวลาของตน
   - FDMA (Frequency Division Multiple Access): แบ่งย่านความถี่ โหนดส่งในความถี่ของตน
   - ข้อดี: ไม่มี Collision แน่นอน, ข้อเสีย: ถ้าโหนดไม่มีข้อมูลส่ง สล็อตนั้นจะเสียเปล่า (Idle)

2. Random Access Protocols:
   - ALOHA & Slotted ALOHA: ส่งข้อมูลทันทีเมื่อมีข้อมูล อัตราความสำเร็จสูงสุดของ Slotted ALOHA คือ 37% (1/e)
   - CSMA (Carrier Sense Multiple Access): "Listen before transmit" ฟังช่องสัญญาณก่อนส่ง ถ้าว่างจึงส่ง
   - CSMA/CD (Collision Detection): ฟังก่อนส่ง และระหว่างส่งก็ตรวจจับด้วย หากพบว่าชนกัน จะหยุดส่งทันที แล้วส่ง Jam Signal และสุ่มเวลารอใหม่ด้วย Binary Exponential Backoff (ใช้ใน Ethernet สายแลน)
   - CSMA/CA (Collision Avoidance): ใช้ใน Wi-Fi (ไร้สายตรวจจับการชนได้ยาก จึงต้องหลีกเลี่ยงการชนล่วงหน้า)

3. Taking-Turns Protocols:
   - Polling: มี Master คอยสอบถามโหนดลูกทีละตัว
   - Token Passing: ส่งต่อเหรียญ Token โหนดที่ถือ Token เท่านั้นที่มีสิทธิ์ส่งข้อมูล
